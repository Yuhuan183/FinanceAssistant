## 1. 資料蒐集清單

研究階段必須先用 WebSearch / web_fetch（或已連接的金融資料 MCP）蒐集齊全，**最優先以公司官方財報新聞稿／8-K 為準**，媒體報導僅作補充與交叉查核。

財報核心數據（本季、上一季、去年同期三欄）：

- 總營收，及季增（QoQ）、年增（YoY）
- 各分部／業務線營收與成長率
- 毛利率（GAAP 與 non-GAAP 如有區分）
- 營業費用、營業利益、營業利益率
- 淨利、稀釋每股盈餘（EPS）
- 下一季財測（營收、毛利率、費用），及全年指引
- 股東回報：股息、庫藏股授權、實際回購金額
- 任何會計口徑變動、一次性項目（投資損益、減損、稅務項目）

法說會與市場面：

- 執行長／財務長關鍵引述（成長動能、需求、策略方向）
- 新產品、新合作、訂單能見度
- 分析師反應：目標價調整、評等分布、平均／中位目標價
- 財報後股價反應與其原因

股價與估值：

- 目前股價、財報後漲跌
- 52 週高低區間
- 50 日與 200 日移動平均線
- 本益比（trailing 與 forward）、PEG、市值
- 關鍵技術支撐與壓力價位

**核對重點**：若不同來源數字有出入，以官方財報為準；注意會計年度與日曆年的差異（如 NVIDIA、Apple 等公司財報季度與日曆季度不同步）。

## 2. 五分頁結構與內容

儀表板固定五個分頁，內容深度應大致平均，避免某一頁過於單薄。

**分頁 0 — 總覽**：6 張 KPI 卡（最關鍵數字）、營收趨勢圖（含財測）、營收組成圈圖、財報重點 5-6 條。

**分頁 1 — 財報細節**：財報摘要表（GAAP/non-GAAP 並列）、分部營收表、獲利能力趨勢線圖、會計眉角與股東回報。務必用 `note warn` 框點出會計口徑變動、一次性項目、GAAP 與 non-GAAP 落差等容易誤讀之處。

**分頁 2 — 未來展望**：財測 KPI、成長動能（結構性引擎＋長線選擇權）、管理層評論引述、方向研判（明確標示為專業推斷）。

**分頁 3 — 股價與估值**：股價／估值 KPI、關鍵價位地圖（橫條圖）、技術面解讀、估值評析、財報後股價反應原因。

**分頁 4 — 三角度投資觀點**：多空對決、三角度觀點、12 個月情境分析、風險因素一覽、後續追蹤清單、免責聲明。此頁是分析的重心，內容須最紮實。

## 3. 三角度與多空分析框架

### 多空對決

並列「多方論點（Bull Case）」與「空方論點（Bear Case）」各 5-6 條，每條一個論點＋佐證。目標是讓讀者一頁看懂兩派理由。誠實呈現——若兩派論點同時成立，明白點出，並指出真正的判斷關鍵變數。

### 三角度觀點

依三種立場各一張卡，每張卡含三個區塊：

- **已持有 · 是否續抱**：支持續抱的理由 / 該留意的事 / 決策觸發點（在什麼價位或事件下重新評估）。
- **考慮買進 · 進場時機**：進場理由 / 風險報酬（壓力與支撐價位）/ 操作參考（分批佈局、資金控管）。
- **長期投資 · 3–5 年**：長線多頭邏輯（護城河、產業趨勢）/ 長線風險 / 每季追蹤指標。

每個區塊用三個圖示分流：`✓` 正面、`⚠` 風險、`🎯` 觸發點／行動。

### 立場中立原則

財報分析不等於投資建議。撰寫時：

- 提供「事實與訊號」供讀者自行判斷，而非「買進／賣出」指令。
- 多空並陳，不偏袒。
- 用「觀察點」「決策觸發點」「操作參考」等措辭，而非「應該買」。
- 若使用者明確選擇某一立場（如「我已持有」），仍保留多空平衡，只是調整詳述的重心。

## 4. 12 個月情境分析方法

提供樂觀／基準／保守三情境，每個情境含價格區間、較現價幅度、成立條件 3-4 條，並標示相對機率傾向（最高／中／中低）。

推估方法：以「forward 本益比 × 前瞻 EPS」為錨，並對照分析師目標價（均價／中位／最高）與 52 週區間，使區間落點有可驗證的參考。

- **基準情境**：機率最高。成長依財測延續但年增率自然放緩、估值倍數大致持平，價格通常落在分析師平均目標價附近。
- **樂觀情境**：成長超預期＋估值倍數擴張。
- **保守情境**：成長動能轉弱＋估值倍數壓縮。

**務必明確標示為「情境推演，非價格預測」**，並用 `note warn` 框提醒機率為定性判斷、非精算結果、勿視為價格保證。

## 5. 專業推斷的寫作要點

「方向研判」與「核心結論」是體現專業度的部分，要點：

- **區分事實與推斷**：財報數字是事實；對未來的判斷是推斷，措辭上要分清。
- **指出張力**：最有價值的洞察通常在「數字強但股價弱」「成長高但能見度低」這類分歧處。
- **點出關鍵變數**：說明哪一個變數最值得監控（如資本支出循環、地緣政治、毛利率）。
- **成長率 vs 絕對值**：高基期下成長率放緩是常態，須說明市場焦點如何轉移。
- **避免空話**：每個判斷都要有財報數據或市場資料支撐。

## 6. 收尾驗證清單

產出 HTML 後，務必逐項驗證：

1. **div 平衡**：`<div` 與 `</div>` 數量必須相等，且逐行累計深度不可為負、檔末歸零。**未閉合的 div 會讓後面的分頁被吞進前一頁而完全看不到內容**——這是最常見且最嚴重的錯誤。
2. **標籤誤用**：檢查 `<div>` 是否誤用 `</p>` 等其他標籤收尾。
3. **JS 語法**：用 `node --check` 檢查 `<script>` 內容無語法錯誤。
4. **數字一致性**：用 Python 重算所有成長率（QoQ、YoY）、占比、估值倍數、情境較現價幅度，確認與表格／文字一致。
5. **分部加總**：各分部營收加總應等於（或合理接近）總營收。
6. **分頁切換**：確認 5 個分頁 `data-t` 與 `data-v` 對應、圖表在切到該頁時才繪製。
7. **免責聲明**：確認分頁 4 含免責聲明，且全文無「保證」「必漲」等不當措辭。

驗證腳本範例：

```python
import re
h=open('dashboard.html',encoding='utf-8').read()
# div 平衡與逐行深度
depth=0
for ln,t in enumerate(h.split(chr(10)),1):
    depth+=len(re.findall(r'<div\b',t))-len(re.findall(r'</div>',t))
    assert depth>=0, f'第 {ln} 行 div 深度為負'
assert depth==0, f'div 未平衡，檔末深度={depth}'
print('div 平衡 OK')
```

```bash
# JS 語法檢查
python3 -c "import re;open('/tmp/c.js','w').write(re.findall(r'<script>(.*?)</script>',open('dashboard.html',encoding='utf-8').read(),re.S)[-1])"
node --check /tmp/c.js
```
